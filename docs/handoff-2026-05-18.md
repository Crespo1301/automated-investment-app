## 1. The IWM "404" — fixed

**Symptom (from API logs):**

```
POST /api/broker/positions/IWM/sell-market HTTP/1.1" 404 Not Found
```

**Root cause:** the route is registered — this was not a missing
endpoint. The handler caught every `ValueError` from
`submit_position_market_sell` and re-raised it as HTTP `404`. IWM is a
$0.98 lot; `minimum_order_notional` is `$1.00`, so the sell tripped:

```python
if position.market_value < settings.minimum_order_notional:
    raise ValueError(f"{symbol} position value is below the $... minimum order guard.")
```

A guard rejection on an *existing* position was being reported as
"resource not found", so the dashboard showed a bare `404` and the
operator could not tell why.

**Fix applied:**

- `broker_adapter.py` — added `PositionNotFoundError(ValueError)`. The
  only place that raises it is the genuine "no open long position" case
  in `submit_position_market_sell` and `submit_position_oco_protection`.
  It subclasses `ValueError` so existing handlers keep working.
- `routes.py` — `sell-market` and `protect-oco` now catch
  `PositionNotFoundError` → `404`, and other `ValueError` → `409
  Conflict` (sub-minimum notional, open sell already pending,
  partial-sell rounds to zero). This matches the `409`s already used
  just above for market-closed and PDT rejections.

**Verify:** retry the IWM sell — expect `409` with detail
`"IWM position value is below the $1.00 minimum order guard."`

(`data-gr-ext-installed`, `data-new-gr-c-s-check-loaded`). These are

## 3. Sell-by-dollars — the bigger fix

**Problem the operator hit:** the dashboard sell control was a percent
dropdown (25/50/75/100%), but the operator wants to sell a specific
dollar amount. Alpaca's position-sell API only accepts a share `qty` —
it has no dollar-denominated sell for closing a position — so a dollar
amount has to be converted to shares on our side.

**Fix applied — end to end:**

- `broker_adapter.py` — `submit_position_market_sell` now takes an
  optional `dollars` argument alongside `percent` (mutually exclusive).
  A dollar request converts to shares against live market value:
  `qty = position.quantity * dollars / market_value`. A `dollars` value
  at or above the position's market value sells it whole. `percent`
  still works unchanged for any programmatic caller.
- **New remainder guard.** Every partial sell (dollars *or* percent) now
  also checks the *remainder*: if selling would leave a lot below
  `minimum_order_notional` ($1.00), it is rejected with a clear message
  telling the operator to sell the full position instead. This is the
  IWM lesson encoded — it stops the dashboard from *creating* new
  $0.98-style stranded lots.
- `routes.py` — `sell-market` accepts `?dollars=` (validated > 0;
  rejects `400` if both `percent` and `dollars` are passed).
- `apps/web/app/page.tsx` — the percent dropdown is replaced by a dollar
  amount input (placeholder shows the position's max sellable value).
  Blank still means sell the whole position. The `sellPosition` server
  action now sends `?dollars=`.

**Why convert on our side instead of Alpaca notional:** Alpaca notional
orders are buy-oriented and have fractional-remainder restrictions on
sells. Converting against the position's own market value is
deterministic, needs no extra quote call, and lets our own
minimum-notional + remainder guards run before anything reaches the
broker — consistent with the repo's deterministic-risk-gate principle.
